## Лабораторная работа №2: Объектно-ориентированное программирование (ООП). Вариант 3
Реализована объектная модель учебного заведения, демонстрирующая ключевые концепции ООП: наследование, инкапсуляцию, полиморфизм и абстракцию.

### Иерархия классов и структура проекта
* **`Person.java` (Абстрактный класс):** базовый класс для всех сущностей. Содержит общие поля (`name`, `age`, `gender`), конструкторы, геттеры/сеттеры, а также абстрактный метод `work()`.
    * **Статическое поле `personCount`:** счётчик, автоматически фиксирующий общее количество созданных объектов типа `Person`.
* **`Student.java`:** наследуется от `Person`. Расширен полями вуза, курса и среднего балла. Демонстрирует **перегрузку методов** (`study()` без параметров и `study(String subject)` с параметром).
* **`Teacher.java`:** наследуется от `Person`. Расширен полями предмета, кафедры и стажа работы.
* **`TeacherAssistant.java`:** наследуется от `Student` (многоуровневое наследование). Описывает студента-ассистента, совмещающего учёбу с помощью преподавателю на кафедре.

### Продемонстрированные концепции ООП
1.  **Инкапсуляция:** все свойства классов объявлены как `private`. Доступ к ним и их изменение происходят строго через публичные методы `get` и `set`.
2.  **Полиморфизм и переопределение (`@Override`):** каждый класс по-своему реализует абстрактный метод `work()`. Динамическое связывание позволяет вызывать нужную реализацию в зависимости от реального типа объекта во время выполнения.
3.  **Приведение типов (Casting):**
    * **Upcasting (Восходящее):** безопасное неявное приведение объекта `TeacherAssistant` к базовому типу `Person`.
    * **Downcasting (Нисходящее):** явное сужение типа от `Person` обратно к `TeacherAssistant` с предварительной безопасной проверкой с помощью оператора `instanceof`.
